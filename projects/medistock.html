CONTEXT & ROLE

项目背景与本人职责

从前端 Web 课程实践出发，完成药品、供应商、入库、出库与库存统计流程，进一步以批次数据和业务单据支撑完整的进销存工作台。

负责业务页面、药品和供应商档案、批次数据、出入库接口、统计图表、单据追溯及备份恢复，完成前后端联调和业务验证。

THE PROBLEM

需要解决什么

出库需要优先使用较早到期的批次，同时排除过期药品。重复提交和并发出库不能造成重复扣减或负库存。

THE APPROACH

如何组织实现

服务端按效期执行 FEFO（先到期先出库），以 SQLite 事务统一更新库存与单据，使用唯一请求标识识别重试。图表由实际演示库记录计算。

PRODUCT DETAILS

让流程完整，
让细节有回应。

批次与效期

管理药品、供应商、批号和效期，识别临期、过期与低库存；拒绝冲突批次元数据。

单据与追溯

采购入库、跨批次出库预览与提交，单据可展开批次明细；有关联业务的档案禁止直接删除。

统计与备份

库存趋势、分类和效期提醒读取当前数据。支持 CSV 导出和经过关联、账本校验的 JSON 备份恢复。

一个值得讲清楚的问题

请求重试时，怎样避免库存被扣两次？

服务端在事务内处理库存与单据，并保存唯一幂等请求标识。相同标识与内容重复提交时复用原结果，不重复扣减；同标识但不同内容则拒绝。HTTP 集成验收覆盖并发超库存与幂等重试。

VALIDATION

实践与验证

  • 8 项库存规则测试及 HTTP 集成验收通过。
  • 实际浏览器完成药品、供应商、入库、跨批次出库和单据追溯。
  • 记录覆盖库存不足回滚、并发出库、重启持久化与非法备份拒绝。
