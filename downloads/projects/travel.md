# 行旅 · 智能旅行规划 Agent

宋浩个人作品集 | 大学阶段项目 · 持续完善

## 项目背景

旅行规划不只需要一段建议，还需要可编辑的日期、活动、交通与费用。项目把 Dify 生成流程接入账号、历史版本和日程工作台。

## 本人职责

负责旅行场景需求分析、Dify 工作流、FastAPI 服务接口、日程编辑、账号与历史数据，以及外部服务联调和流程验证。

## 技术栈

Python / FastAPI / Dify / RAG / SQLite / SSE

## 核心功能

### 生成与反馈

按出发地、目的地、日期、预算和偏好准备需求，用 SSE 展示状态与正文，对超时和异常响应提供提示。

### 编辑与版本

按天增删活动，调整时间、地点、交通和费用。历史支持检索、分页与修订，保留原始方案和新版本。

### 保存与导出

SQLite 保存账号、偏好和历史；预览、Markdown、日历和打印读取同一份编辑结果。没有模型配置时可使用标明来源的手动模式。

## 实现方法

Dify 工作流连接知识检索、规划与检查；FastAPI 校验请求并转发流式结果。仅在生成完成后保存，通过独立规则检查标出需要确认的内容。

### 怎样让生成、编辑和导出保持一致？

接口层保存完整方案与修订版本；编辑后由统一日程数据生成预览和导出内容。生成流程同时检查日期、时间与预算，并把状态变化反馈到页面，形成从输入到保存、导出的完整链路。

## 实践与验证

- 67 项 pytest 通过，覆盖接口、流式响应、账号、天气与规则。
- 浏览器验证创建、编辑、保存、下载、历史检索与账号隔离。
- 完成真实 Dify 生成联调，并提供 Docker 与本地启动方式。
