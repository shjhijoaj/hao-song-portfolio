CONTEXT & ROLE

项目背景与本人职责

围绕小型设备的温湿度、电流、振动与在线状态监测，组织传感器驱动、实时任务、通信协议、网关解析与可视化面板，实现从采样到告警的完整流程。

个人项目 · 嵌入式与设备监测

负责传感器总线抽象、C 协议编解码、FreeRTOS 任务与队列、C++ 网关、采样落盘和监控面板，并完成故障注入、看门狗恢复及持续采样验证。

C / C++17FreeRTOSUART / I2CCRC16QEMUHTTP

THE PROBLEM

需要解决什么

连续字节流可能出现错帧，采样任务也可能停滞。系统需要识别数据完整性、区分越限告警与设备离线，并在异常后恢复采样链路。

THE APPROACH

如何组织实现

逐字节状态机检查帧头、长度和 CRC16；FreeRTOS 队列连接采样与发送任务，由独立看门狗监视心跳。网关解码后按统一阈值生成告警、写入 CSV，HTTP 面板展示趋势与状态。

PRODUCT DETAILS

让流程完整，
让细节有回应。

采样与通信

BME280、INA219 与 MPU6050 驱动采用可替换 I2C 总线接口；串口、TCP 与离线回放汇入统一帧解析链路。

监测与告警

面板展示温度趋势、采样记录、设备在线状态及温度、电流、振动、传感器状态告警；支持 HTTP 采样接入。

故障与恢复

采样、发送、健康上报与看门狗分工，任务通过队列交换数据；心跳超时触发系统复位，保留复位计数以核对恢复结果。

ENGINEERING

沿一条链路，理解项目。

  1. 01传感器 / I2C
  2. 02FreeRTOS 采样与队列
  3. 03UART / CRC16 帧
  4. 04C++ 网关与 CSV
  5. 05HTTP 监控面板
一个值得讲清楚的问题

采样任务停滞后，怎样确认系统真正恢复？

主动注入采样停滞，由看门狗检查采样心跳并触发复位。复位计数存入 .noinit 段，结合启动日志、帧序号和恢复后的遥测数据，核对复位发生及数据链路重新工作。

VALIDATION

实践与验证

  • MSVC 与 GCC 的协议、网关、传感器三组主机测试均通过。
  • Cortex-M3 固件交叉编译与 QEMU 故障注入验证通过，检查看门狗复位后的采样恢复。
  • 600 秒稳定性记录：1202 帧、错帧 0、看门狗复位 0；保留原始日志、指标与曲线。
